# Design: one current governed commercial projection

## Decision and gate

**Architecture gate: independently checked PASS for the reconciled planning contract; implementation/apply: NO.** The final DB-clock-checked transaction's **atomic commit is the sole public-effect linearization**; readback only observes its result. The design preserves exact generation adoption, trusted-DB completeness/integrity, fenced baseline retry/archive, `public` privilege hardening and separate prebuild handoff. One current projection remains isolated from source; one scoped Clerk release-policy approval permits independently postcommit-**source**-verified forward deltas without per-price consent, renewed expiry or a mandatory post-publication outage.

## Architecture choices

| Option | Tradeoff | Decision and rationale |
|---|---|---|
| One current typed projection + exact retained deltas | Copies initial catalog once, adds guarded promotion and intentional source/public divergence | **Choose:** ordinary joins, bounded changed-row writes, independent verification before public effect. |
| Per-release temporal rows, time-travel selection, `btree_gist`, full snapshot streams | Storage/query/custody complexity and historical-byte serving | **Reject:** neither required nor selected; correction creates new current state instead. |
| Source reads with approval metadata, or publisher rescan | Smaller apparent implementation but imports verification-to-effect drift | Reject: publisher consumes exact independently verified bytes only. |
| First baseline staged directly in empty current tables | One fenced build at a time; rejected sealed attempts may require one retained full baseline archive each | **Choose:** no second live/staging dataset or catalog-sized activation; archive required rejected bytes before bounded cleanup, never reuse a rejected FROZEN attempt. |
| Clerk session + scoped DB grant + narrow review route | Approval ingress becomes trusted infrastructure | **Choose:** no Ed25519, generic administration UI, second human/service approval or self-enrollment. |
| Bound internal payload cache + absolute authority decision | Requires time-aware output and complete external-cache enforcement | **Choose:** useful caching remains; blanket all-route `no-store` is unnecessary. |

### U12a2 verifier authority boundary

U12a2 is split into **A → B → C** before U12b: **A** establishes one dedicated verifier LOGIN principal and its least-privilege ACL; **B** binds that authenticated caller to exact U12a1 canonical envelope bytes; **C** durably admits the bound envelopes. U12b is split into **U12b1 → U12b1b → U12b2**: **U12b1** creates only immutable g>0 generation/promotion storage and typed operation/repository contracts, binding the sealed admission, manifest, predecessor/result lineage, policy/health/build, publishing adoption, and indispensable audit/evidence references; it has no current-row or generation mutation, `promote_delta`, source rescan, recovery, renewal, or public/serving effect. **U12b1b** adds only immutable, deterministic typed storage and validation for each admitted six-entity delta after-image/tombstone, bound to its sealed admission and manifest; it has no `promote_delta`, serving/current-row mutation, generation advance, source rescan, recovery, renewal, or public effect. **U12b2** is the sole owner of the final-DB-clock-checked `promote_delta` transaction and mandatory PostgreSQL atomicity/CAS proof. The dependency chain is **U12a2-A → U12a2-B → U12a2-C → U12b1 → U12b1b → U12b2 → U12c → U11b4**. No later slice is complete or authorized by the earlier one.

The verifier role is distinct from owner, app, and runtime, and is `LOGIN NOINHERIT NOSUPERUSER NOCREATEDB NOCREATEROLE NOREPLICATION NOBYPASSRLS`. App/runtime receive no membership, inheritance, `SET ROLE`, or function-execution route to it; PUBLIC receives no verifier capability. Verifier attribution comes from PostgreSQL `session_user`, which remains the original authenticated caller across a SECURITY DEFINER call; `current_user` changes to the definer and is therefore invalid provenance. Every future verifier admission function must use a minimal NOLOGIN owner, `SECURITY DEFINER`, fixed `search_path = pg_catalog, pg_temp`, fully qualified objects, PUBLIC/app/runtime EXECUTE denial, and an explicit verifier-only EXECUTE grant. U12a2-A establishes that future grant contract without creating admission storage or the admission function; credentials and trust enrollment remain separately authorized.

Harden `scripts/postgres-{backup-r2,recovery-r2,recovery-smoke}.mjs`, bootstrap renderer CLI and restore checks together. Keep `public` dump selection and explicitly verify coverage of all protected tables, functions, constraints and evidence dependencies; ACL-free restore must recreate intended ownership/roles/defaults and run independent effective-privilege checks before serving. Old recovery grant files must not silently restore DML. Existing app shares environment/process trust: separate clients/roles restrict stolen individual DB credentials, not whole-process compromise when approval/publisher secrets coexist. Server-only modules are not OS isolation. Source-job environments exclude verifier/approval/publisher secrets; DB owner, enrolled observers, Clerk and approval/verifier bridges remain trusted infrastructure.

Retain canonical consent/contract, enrollment proof used by consent, baseline manifest/digests, exact delta BEFORE+AFTER, verification/source evidence excerpts, operations and indispensable audit through **latest referencing authority expiry + 180 days**. Revocation does not shorten it; extend only for active references or explicit holds. Required rejected/unpublished proof uses declared validity end +180d. A sealed initial baseline cited by candidate/verification/review cannot be reconstructed after its nonpublic rows are purged: retain its exact canonical rejected baseline bytes/evidence in a content-addressed archive first. **One full baseline artifact per such attempted initial baseline is justified**, not one snapshot per refresh/release. Unsealed partial uploads retain only required proof, otherwise finite upload/cleanup deadlines; no invented complete baseline or unnecessary cookies/tokens/PII. For LIVE lineage, current unchanged rows plus retained changed/deleted before-images support bounded independent reconstruction, never runtime historical selection. This avoids unnecessary full copies but does not erase rejected-baseline storage cost.

Protected chunks are sealed after retrieval/hash checks; detected evidence loss/corruption atomically records negative dependency health/restrictions, whole surface if unknown. GC-only custodian computes transitive authority/current-fact/correction/hold/abandoned-attempt references, audits disposition and deletes only expired unreferenced chunks in bounded batches; source history's 90-day cleanup cannot shorten custody. Active lineage dependencies may extend retention; measure growth. Abandoned-build row cleanup follows the fenced archive protocol below, not evidence GC. Backups are encrypted, access-restricted and finitely retained with aligned deletion obligations. PostgreSQL data checksums, verified backups and bounded integrity verification with named operational ownership are enablement prerequisites. Restore requires separate authorization, disabled traffic, new incarnation, latest revocation reconciliation and independent raw-evidence/constraint/privilege verification before new exact adoption and separately authorized identity handoff; a backup cannot resurrect authority.

## Non-circular deployment and baseline sequence

```text
Separate enrollment/config authorization -> reserve domain deployment UUID + publication UUID
Config custodian -> inject immutable deployment-specific selector before candidate creation/build
Platform -> protected production-target deployment, exact Git source; commercial routes fail closed
Assembler -> source snapshot -> preloaded current tables FROZEN; independent verifier -> seals
Verifier -> actual deployed artifact/provenance + reserved identity + exact policy/build verification
Human -> live Clerk/session + DB grant -> review/challenge -> canonical explicit approval
Publisher -> final DB check + atomic COMMIT: g0 LIVE + terminal authority + adoption/audit/proof
Runtime -> committed exact I + live time before E -> serve; readback only observes, no config/traffic action
Existing pinned-deployment guard -> later separately authorized validation, never creates authority
```

The new selector is version 2: `{version,domain,target,scope,deploymentId,publicationId,incarnation}`; `deploymentId` is the **preallocated domain UUID**, not Vercel's later `dpl_*` ID. Its separately authorized **prebuild domain-selector handoff** reserves one exact publication, not an already-active authority or a latest-authority selector. Publication is DB-only and independent of configuration: after persistence, the custodian separately verifies the resolved exact I against that reserved selector (a handoff readback, not automatic config mutation); any changed selector needs separate authorization. The proposal's publish/readback/handoff separation is preserved without rebuilding the approved deployment. Resolved I adds sealed full SHA, candidate digest, policy/build and platform provenance from that exact record, checked against the actual packaged build contract and reservation. Version 1 remains unproven for this workflow, not silently translated. Prebuild configuration deliberately lacks the not-yet-computable candidate digest/platform ID; this is a versioned resolver change, not a claim today's parser supports it. Generate the build contract from actual packaged query modules/dependency versions, excluding its own output; full release SHA comes from attributable platform provenance, never a future SHA written into its own source.

Before creating a candidate, separately authorize deployment protection, selector injection and creation of a production-target deployment **without automatic alias assignment**. Verify platform-origin GitHub repo/ref/full SHA, project, target, READY artifact, build/query digest, generated hostname and observed preconfigured domain selector after creation; caller-controlled `meta.githubCommitSha` or env values alone are insufficient. Use a narrowly authenticated bootstrap-proof mode reporting reservation/build identity but never `active:true`; independent artifact/provenance verification does not invoke the public authority guard. If the current Vercel mechanism cannot demonstrably inject immutable per-deployment config prebuild, preserve Git provenance and withhold alias/traffic changes, **the deployment design gate BLOCKS**; do not invent a working command or configure/rebuild after approval. A deployment that never obtains authority stays fail-closed.

First baseline only when no LIVE projection exists: `begin_baseline(expectedEpoch)` locks EMPTY control, verifies all six tables empty/no pending cleanup, allocates new `buildAttemptId` at the current monotonic epoch and enters BUILDING. Export one read-only REPEATABLE READ source snapshot; keyset-stream into **actual current tables while nonpublic**, then FROZEN-seal complete key/count/row/chunk manifests. Every bounded write/seal carries attempt ID/epoch, locks control and checks active state/deadline, so freezing fences late uploads. Independent verifier imports that same still-live source snapshot to recompute source/evidence; a separate connection reads committed FROZEN rows (invisible to the older imported snapshot). Compare and seal before releasing export/human review. Snapshot loss/inconsistent roots abandons the attempt, never combines snapshots. Source DML continues; no source freeze, second active staging dataset or live authority is needed.

A FROZEN rejection/expiry **cannot be reused**, nor can a failed partial BUILDING upload. Guarded `abandon_baseline(attemptId,expectedEpoch,reason)` and activation lock the same control row/CAS: exactly one wins. Abandon atomically marks the attempt ABANDONED, invalidates all of its build/verifier seals, challenges and approvals for use (retain their historical bytes), increments `build_epoch`, and sets the cleanup fence before any purge. Catalog remains BUILDING/FROZEN and nonpublic during cleanup; every old-epoch upload/activation/retry rejects. Expired attempt use rejects even before explicit abandonment; caller/operator drives cleanup, not a new scheduler.

For required rejected/unpublished proof, custodian streams the now-immutable canonical attempted baseline/evidence into bounded content-addressed archive chunks, verifies retrieval/hash/length/key counts against an archive manifest of the exact rejected canonical bytes, then seals an archive-integrity receipt. Preserve the original declared manifest and any mismatch separately; a rejected producer digest cannot stand in for actual archive bytes. Partial uploads have an explicit partial inventory, never a fabricated complete-baseline manifest. This proves preservation, not baseline validity; retain rejected assertions and failed verification truthfully. Missing/corrupt archive blocks purge/reuse. Guarded cleanup deletes only that ABANDONED attempt's BUILDING/FROZEN rows in bounded FK-safe batches, with resumable progress and epoch/cleanup checks; partial-upload chunks use the same deadline/reference rules. Only proven empty tables and completed required archival allow control→EMPTY/new attempt. No LIVE rows can enter this cleanup, and the incremented epoch is never undone.

Final activation checks active buildAttemptId/epoch, FROZEN state, unexpired seals/approval, constraints/manifests/evidence and no cleanup fence; it transitions control/attempt→LIVE, creating g0, exact adoption and authority atomically in constant metadata work, **not O(catalog) inserts**. That commit makes g0 available to an ordinary eligible runtime read immediately; no later publication step is required. A committed but ineligible LIVE g0 is recovered forward, never sent through baseline cleanup. No table/partition swap or per-release dataset pointer exists. Once LIVE, only guarded deltas modify current rows. Initial evidence states actual offer/source coverage: six known source definitions are not a known full EAN universe; use distinct `(source,EAN)` units, supplied expected universe or explicit unknown, gaps/counts/watermarks, and real historical origin. Unknown controlled-write lineage cannot be laundered into baseline.

With a LIVE projection and ADMITTED g, a new release or policy adopts current g/original baseline + retained delta evidence through fresh independent release/build/current-state verification, exact candidate and human approval; **no second baseline build**. Admission-INELIGIBLE g instead requires the new forward recovery below. Activation CASes reviewed g/lineage/health; drift needs new verification and a new reviewed payload if its binding changes. Different exact deployments may coexist only with their own exact `GenerationAdoption` under the **same effective policyDigest**. A representable policy/scope change requires fresh consent and independent current-g adoption, CASing old policy/g/health and installing new effective policy/health/adoption with audit, not rewriting data/resetting g. Previous-policy authorities then fail exact digest equality. Historical admission policy remains evidence, not current read policy. An incompatible schema needing a new baseline is a separately designed/authorized migration, outside this workflow. No implicit supersession or config change.

## Narrow consent and lifecycle contracts

Add only `/admin/catalog-authority/[operationId]` and scoped `/api/admin/catalog-authority/` prepare/approve/activate/inspect/revoke/correct endpoints. They never launch source writers, enrollment, deployment or traffic actions. Reuse current Clerk/admin admission, then validate live non-null userId/session and uncached DB publication-specific action/scope/target/policy grant at every handler/DAL. Initial enrollment is separately authorized custodian work; generic admin, a DB URL, fixture receipt or environment allowlist cannot approve. One human may perform accountable technical and approval roles; independent verifier logic/credential still must recompute actual inputs rather than trust producer PASS.

Prepare reserves operation IDs and a random 256-bit, session/user/payload-bound one-use nonce. Review displays exact domain/platform deployment, full SHA, scope/target, candidate/baseline/policy, allowed mutations/limits, verifier result, coverage/unknowns/original source ages/degradation, expiry, revocation and retention. Consent is explicit, not inferred from viewing. POST validates bounded declared content type/schema, trusted same-origin Origin (not forwarded Host), Fetch Metadata where present, session-bound CSRF token, nonce/deadline and full canonical request equality. Server reconstructs actor/bindings/time; atomically consumes nonce and stores canonical attributed receipt. Missing/tampered/swapped/replayed input fails; exact idempotent retry recovers its receipt. Escape evidence as data, disable wildcard CORS, make challenge/consent responses private and non-reusable; retain only nonce/session proof hashes, not secrets. Publisher cannot manufacture consent by submitting a userId.

Use an absolute E shared by candidate technical-admission validity, approval and authority, bounded by policy and the approving grant's original expiry; every durable challenge and receipt records that original grant expiry and cannot extend it; `technicalVerifiedAt <= approvedAt <= finalCheckedAt < E`. Recorded activation transition time denotes this final transactional check, **not the unknowable durable commit instant or a promise of active success**. Challenge is shorter-lived; verifier/executor grants must be valid when used. Refresh verification has its own admission deadline ≤ publisher E, checked in the final transaction, and evidence-age limits; its sealed result remains historical proof after that use. Runtime evaluates live current time against the exact reader's E/adoption/evidence integrity/source-age limits. A historically admitted generation does not become corrupt merely because its original publisher later expires. Observation, technical, approval, activation, refresh and expiry clocks remain distinct. Retries, consent or correction never rejuvenate `last_checked_at`, `scraped_at` or historical `verifiedAt`.

Authority transitions PENDING→PROMOTED/REJECTED and PROMOTED→REVOKED; revoked/rejected/legacy states never revive. Expiry changes eligibility, not original times. Grant withdrawal blocks new actions but does not rewrite old consent: incident response separately revokes affected authority. **Release-authority revocation** invalidates that I/adoptions, not historically admitted data. **Data/evidence restriction** invalidates the affected generation/fact dependency closure across all authorities; unknown boundary denies the commercial surface. Incident requests explicitly declare these scopes (both when needed). Rejection of an unpromoted refresh does not revoke authority. Disabling publication execution neither revokes nor restores anything.

## Authority × generation eligibility

Historical `GenerationReceipt` admission and current `GenerationAdoption` answer different questions. **ADMITTED/INELIGIBLE are live eligibility outcomes, not a persisted admission workflow**: the atomic result needs no later state transition to become readable. Data health is independently CLEAR/RESTRICTED/UNKNOWN. An adoption evaluates VALID/INELIGIBLE from its immutable bindings and live expiry/revocation/health. VALID requires still-eligible exact I, live `t < I.E`, and `I.policyDigest = adoption.policyDigest = control.policyDigest = payload.policyDigest`, plus exact incarnation/current g/lineage/health/build and required evidence/consent. An expired reader is ineligible; this alone does not invalidate historically admitted data for a different independently eligible reader. Historical publisher I/policy need not equal the reader; there is **no implicit policy compatibility**.

| Historical admission / current state | Exact reader authority A or B | Current protected read / action |
|---|---|---|
| Atomic conforming result visible before A.E; ADMITTED, CLEAR | A's exact adoption committed with g; live validity holds | Serve bound facts immediately, even if publisher readback is delayed/lost. No second write, operator acknowledgement or mandatory outage; publisher role alone is insufficient. |
| ADMITTED, CLEAR; historical A later expires or release-revokes | B has its own still-VALID exact adoption/equal effective policyDigest | B may serve; A may not. Valid admission is not retroactively corruption or expiry of data merely because A ended. |
| ADMITTED, CLEAR | Any reader lacks adoption, has old g/health/build, or unequal policyDigest | No current read. Fresh independent machine adoption under already-approved unchanged I/policy is allowed; new I/policy/scope/validity also needs fresh human approval. |
| ADMITTED; data/evidence RESTRICTED or UNKNOWN | Any A/B, even with a matching receipt | Deny affected facts and all derived dependencies; unknown boundary denies whole surface. Independent repair verification is required, not another release's old adoption. |
| Publishing operation first observed at/after its E and INELIGIBLE; no established earlier eligible admission | Any A/B, including unexpired B | Historical result never serves under that admission; advanced g and final-check time do not prove earlier eligible visibility. B cannot automatically inherit or adopt that ineligible g in place. |
| Generation/effect INELIGIBLE, not merely an expired reader | Any reader | Protected unavailable; separate fresh independent verification under valid release/policy capability must create **new forward no-op/corrective g+1 and new adoption**, never revive old admission or select old rows. |
| ADMITTED g, but no valid exact read authority | Any reader | Protected unavailable until a separately verified/approved exact authority obtains its own valid current-g adoption; data need not be rewritten merely because no reader is authorized. |

Every promoted g creates the publishing I's exact adoption from independent verification; another already-approved release uses `adopt_generation(I,verificationId,expectedGeneration,expectedHealthVersion,requestKey)` to independently machine-verify that exact g/build/health before a current read (no per-delta human consent). It independently verifies historically admitted current g and CAS-checks exact policy equality, g/health and that I's still-valid approval/verification; it never copies another I's receipt or rewrites candidate consent. A late first observation of an ineligible result follows the forward-recovery row instead. Earlier eligible history may be established by existing attributable observations/adoption evidence; final-check time alone cannot establish it. Missing such history after publisher expiry is not permission to guess, while an ordinary pre-expiry read never needs to persist an observation first. Health/policy changes require a newly checked exact adoption; negative health always denies its dependency closure. A prior bound payload may finish only its original permitted lease under the cache rules, never label new rows with an old adoption. Recovery capability is distinct from read eligibility so a restricted/ineligible predecessor can be inspected and independently corrected without becoming serveable.

## Source commit → independent verification → current delta

1. Keep existing issue approval, one-source/batch, exact confirmation, prewrite, kill switch, advisory lock, no-create/no-partial and postwrite/baseline controls. Extend `ActiveWriteTransaction` and the five adapters with typed source-write/capture procedures: lock affected source/dependency keys deterministically, capture actual BEFORE, execute typed writes, capture actual AFTER/history IDs through SQL return/readback, and seal operation/items/prewrite evidence in the **same source transaction**. Reports remain supplemental. A targeted deferred seal check rejects subsequent uncaptured changes to captured keys in that transaction; no universal source triggers/revision counter. Capture failure rolls back source; unknown commit requires operation discovery before any retry.
2. **After source commit**, independently run the existing postwrite and freshness-baseline verification. Use separate read-only source credentials and consistent committed observations, check actual selected identities/values/history/no-create and authentic operational evidence against retained capture/raw observations. Producer PASS/file existence/hash alone is insufficient. New source drift before this audit may cause conflict/failure; never skip the audit because capture exists. Missing/failed verification leaves source committed but public rows unchanged. Trusted verifier failure recording persists audit and applicable negative restriction together. Runtime health views also derive uncertainty from immutable PENDING captured delete/unavailability keys using current projection observation/SLA, so verifier stoppage cannot bypass their original cutoff; this is negative-only capture metadata, not mutable-source serving or a source role's permission to edit restrictions. These restrictions can reduce eligibility, never certify new facts. Record durable observation time separately from report `committedAt`.
3. Against current g, independent verification constructs complete governed after-images from **only the permitted changed fields of that exact source delta** and current governed predecessor. Bind source BEFORE/AFTER separately from governed BEFORE/AFTER, exact policy/authority, observations, affected keys/dependencies, expected g/health version and all evidence/audit references. Unknown source differences in unchanged fields are not copied; they may remain source-only when irrelevant to the approved patch. Drift in changed fields/dependencies needs proven successor/precedence resolution or conflicts. Seal immutable verification; publisher receives references, not arbitrary replacement bytes.
4. `promote_delta(operationId,verificationId,expectedGeneration,expectedHealthVersion,requestKey)` locks catalog control/affected current keys, checks exact eligible publishing authority/policy/capabilities/seals and predecessor digests, CASes g→g+1 and applies only sealed full results/tombstones. Rows, g/lineage receipt, complete expected-key/count delta manifest, publishing I's exact adoption, indispensable evidence/audit and operation outcome commit **together after the final DB clock check**. That commit is the sole public-effect linearization: an ordinary current read before exact authority E can serve without waiting for publisher readback. No source rescan/network call/public-read lock. CAS/audit failure or expiry before final check rolls back projection effect, not source; an observation at/after E follows the live-eligibility/forward-recovery matrix, not guaranteed rollback. Read back exact outcome/current eligibility; notifications only accelerate eviction.

```text
Controlled writer -> source TX: actual BEFORE + typed write + actual AFTER + PENDING capture
Source COMMIT -> independent postwrite/baseline -> verifier seals delta against current g
Publisher -> DB TX: authority/evidence/predecessor checks + g CAS + current rows + audit/proof
DB COMMIT -> runtime RR + live exact-authority expiry check -> serve; lost response -> read-only discovery
Bad promoted delta -> restriction -> new independently verified correction -> same forward CAS
```

Initial policy permits only explicitly listed existing-row Product/offer changes and real history append for supported controlled sources, plus a separately specified forward-correction class. Representation is not writer authorization: promotion admin, cleanup, ingestion/reconcile, discovery/EAN rekey and source config adapters remain **source-only until their exact adapter/evidence policy is approved**. Supporting a new/wider class requires fresh contract verification/consent. Existing production writer authorization is not supplied by this design.

| Case | Exact rule |
|---|---|
| Shared Product identity | Source-specific name/brand/image/category updates promote only with explicit approved source/field precedence, exact current predecessor and independent conflict resolution. Otherwise the operation conflicts/remains source-only; no invented merge or last-writer-wins. EAN rekey additionally needs atomic dependency closure and an approved adapter. |
| Inserts/deletes/membership | Approved inserts prove absent key and live dependencies. Verified deletion applies explicit tombstone to evidence and removes current rows/dependents in one transaction; tombstoned fact cannot reappear without a new verified insert. Membership replacement includes complete set and promotion atomically, never an intermediate empty/source-wide set. |
| Partial sources | One controlled source operation is all-or-nothing; never salvage failed rows as batch PASS. Independently verified operations from different sources can promote separately with truthful partial coverage. Shared identities still follow conflict policy. |
| Concurrent g change | One CAS wins; even disjoint loser needs a new independent verification attempt against current g. Original source delta remains immutable. No blind retry/rebase or copying current source. |
| Failed delete/unavailability verification | Previous verified observation remains degraded/uncertain, never newly verified stock, only until **original** `last_checked_at + existing effective per-source SLA`. On/after cutoff hide affected current facts and derived claims; independently eligible history may remain explicitly historical. Trusted restrictions identify boundary; unknown boundary denies entire commercial surface. Verified tombstone/unavailability applies normally. |
| Ordinary historical/partial facts | Preserve policy-permitted history and existing freshness semantics; no invented coverage percentage or blanket 24h rejection. Failed-delete cutoff is not an unlimited historical-price escape. Invalid/future observation times fail verification; failure time never resets SLA. |

**Intentional divergence/recovery:** source may advance while projection stays stale, indefinitely if nobody promotes. An operator must inspect PENDING age, source commit/postwrite/baseline status, expected/current g, dependency conflicts and rejection reasons; recover missing reports/proof from retained operation, rerun independent verification or abandon/reject, then explicitly request promotion. A successor after a failed promotion uses its own exact captured patch against current projection; it cannot inherit an unverified predecessor wholesale. If changed-field lineage cannot resolve, leave source-only until a newly authorized/verifiable operation exists. No automatic source restoration/rewrite or scheduler is added. Set finite policy-specific pending-age warning/escalation thresholds and named ownership before enablement; existing alert/report inspection surfaces expose oldest pending age, remaining source SLA, conflict and verification backlog. Alerts/manual recovery mitigate but do not guarantee eventual promotion.

## Forward correction, atomicity and recovery

A bad promoted operation first receives an attributable restriction over its dependency closure; observed decisions evict, all instances enforce the same ≤30s bound, and an unknown boundary blocks the commercial surface. `prepare_correction(badOperation,currentGeneration)` takes retained governed before-images, original changed-field mask and current rows. Revert only those fields whose current value/predecessor still matches the bad operation's explained successor chain; preserve all unrelated intervening fields/rows. Overlapping later changes need explicit independently verified resolution, otherwise conflict. No blind full-row inverse. Reinsert/delete correction must verify complete referential closure and original history/source times.

Correction is a **new operation and new independently verified/audited forward g+1**, through `promote_delta`, referencing the bad operation and its successor lineage. Its approved class permits governed-only correction without requiring source restoration: independently verify the original committed-source delta/postcommit evidence, retained before-images, current postcommit source observations and the explicitly explained source/projection divergence, plus current governed predecessor. This is new verification after source commit, not reuse of the old PASS or a claim source was restored. If that proof/policy/capability/authority is unavailable, facts stay restricted. The corrective transaction may inspect a restricted or admission-INELIGIBLE predecessor only under still-valid release/policy **recovery capability**, not read authority over that predecessor. For a publishing operation first observed after its E and ineligible, independently reverify the entire ineligible effect/dependency closure, retained source/before-images/current facts and new result. A **forward no-op** is allowed when independently verified values stay identical: still create a new operation, g+1/lineage, evidence/audit and adoption atomically; never endorse old g or reuse the original effect identity. Preserve unrelated verified changes; unresolved facts stay restricted. A policy not permitting this recovery requires fresh contract verification/approval. Clear only independently resolved data restrictions atomically with new effect; never clear release revocation or old admission ineligibility.

`activate_authority(operationId,approvalId,verificationId,expectedReservationVersion,expectedGeneration)` atomically links indispensable PROVENANCE/AUTHORIZATION receipts, terminal promotion/publication state, technical/consent metadata, g0 or current-g adoption, audit and recoverable proof. Existing LIVE projection generation is not reset by adoption. If g0 or a later g is admission-INELIGIBLE and no valid recovery authority remains, fresh independent recovery verification and human approval may bind a new I to that explicit predecessor and verified forward result: guarded activation atomically creates terminal I **with new g+1/adoption**, never read adoption of the ineligible g. This is a separately requested recovery operation, not lost-response retry or baseline rebuild. Revoke uses an action-specific Clerk receipt binding exact I/reason/revocation scope/expected version; publishable machine refresh/correction consumes approved policy and independent verifier proof, not fresh human per-delta consent.

`promote_delta` and `activate_authority` enforce a final authoritative `clock_timestamp()` validity check after waits/validation in their guarded transaction, not transaction-start `now()`. Expiry at/before that check aborts and preserves prior persisted state. The **same transaction's atomic commit is the sole public-effect linearization**: current projection rows/control, g/lineage, indispensable evidence/audit, publishing adoption and operation outcome are already durable together. Ordinary conforming promotion visible before exact authority E serves immediately; there is no second publication procedure, transaction, acknowledgement, receipt-state change or readback gate. Transaction/indispensable-audit failure rolls back completely. Expiry after the final check need not preserve prior selection: if the result is first visible at/after E, live eligibility reports historical/INELIGIBLE, never serving or active success under that authority. An already historically admitted g and another reader's own valid adoption are governed by the matrix, not automatic inheritance.

Retain **`[finalCheckedAt, observedReadbackAt]` as a bracket**, not an exact durable commit timestamp. An ordinary primary-DB read, including runtime, may observe the committed result before the publisher receives its response; that observation is not a state transition. A bracket straddling E does not prove which side of E the commit occurred on. Runtime uses live current time at eligibility evaluation and before protected emission, never a precommit/snapshot timestamp as a renewed lease. Postcommit readback/discovery only returns exact persisted proof, observed time and current eligibility; attributable observation/access audit is diagnostic, not authorization or a prerequisite for ordinary serving. If the current generation's publishing operation is first observed after its E and is ineligible, separately verify a forward no-op/corrective g+1/adoption; do not revive it by retry, later clock, B's longer expiry, or an in-place receipt. Lost response never causes another activation, renewed validity or compensating rewrite. Independent postcommit **SOURCE** verification still precedes publication; it is not moved after public effect.

Idempotency scopes `(domain,scope,action,clientKey)` for authority and `(catalog,action,clientKey)` for delta; source capture uniquely binds source/run/attempt. Compare **entire canonical request bytes and digest**, including I/policy/candidate/approval/evidence/nonce/actors/expiry/predecessors/expected versions; changed payload conflicts. Unique reservation/approval-action and ordinary-refresh source-operation constraints prevent duplicates under different keys; a correction has its own unique operation/effect identity referencing, not reusing, the original source operation. Exact retry recovers original proof, not another effect. Competing activation for the same reservation conflicts; explicit supersession requires a newly approved exact reservation/contract, never silently repoints old config. Lock order: necessary grant/receipt → identity reservation → catalog control → sorted affected keys → operation/audit; source transactions never take catalog locks, publishers never source locks.

Lost response means unknown until scoped discovery, for source and publication alike. Inspect returns original publication/promotion states and IDs, domain/scope/target, domain/platform deployments/full SHA, candidate/policy/baseline/generation/lineage/evidence, linked consent/verifier, approving/executing actors, all original times/expiry/transitions and current eligibility/reason. Recovery after expiry may return historical proof but cannot activate/promote again, duplicate original audit, renew validity, compensate or select another I. Recovery-access audit is separate. Authority/release rollback may use only another independently eligible exact I with its own VALID adoption for **current** g/lineage/health/build and exact effective policyDigest; different identity needs separately authorized handoff. Data correction never selects retained historical bytes.

## Runtime and bounded caches

`withAuthorizedCatalogRead(selector,normalizedQuery,load)` resolves exact I and supplies only a projection adapter. Use one short read-only **REPEATABLE READ** primary-DB snapshot of exact authority/reservation/adoption/build/policy, control g/lineage/health, generation receipt/evidence and all joined current inputs. Combined detail/history, offers/promotions, metadata/body and counts share that boundary. Atomic promotion yields all old or all new, never mixed state; no public-read lock or historical row query. Evaluate eligibility with **live current time**, not RR transaction-start time; recheck exact I.E before emitting protected bytes. A visible conforming result before E is readable without any prior publisher observation or additional DB write. No valid exact authority/adoption means **protected unavailable**, never latest PROMOTED/source fallback or false 404.

**Integrity/completeness threat boundary:** PostgreSQL owner, storage engine, transactions, FK/unique/check constraints and hardened procedures are trusted. The application does **not** cryptographically prove physical absence on each query. Guarded baseline writes establish the manifest's complete expected key sets/counts; guarded deltas validate insert absence, delete/update predecessors, exact affected-key sets, membership/dependency closure and resulting counts, then atomically bind the new receipt's manifest to predecessor manifest + exact delta. FK/unique/check constraints alone cannot prove every expected row exists: trusted exclusive write paths maintain that invariant and deny direct DML. Row hashes aid audit/recovery and changed-row checks; they are not the sole runtime absence proof.

At every successful decision renewal, verify compact critical canonical receipts/manifests/seals and exact control generation/receipt and live eligibility, I/adoption/equal policyDigest/lineage/build, current evidence-dependency health and DB integrity status. Expected-set manifests can reference sealed baseline chunks plus exact deltas and compact count summaries; renewal verifies those bindings/status, not an O(catalog) scan or replay. Verify large raw evidence bytes on ingestion, independent verification, restore/recovery and bounded integrity audit. Detection of missing/corrupt required bytes atomically persists audit + negative health/restrictions for dependency closure (whole surface if unknown); request-local denial is immediate, other instances follow the original ≤30s/earlier-expiry bound. Unknown/stale required integrity status prevents renewal; outages can use only the preexisting immutable lease. Operational audit bounds/owner/receipts must be established before enablement using authorized existing/operator execution, **no new scheduler**.

A current-table absence, count or ranking is trusted only inside the same RR boundary after admission/adoption/manifest/health checks, using constraint-consistent joins and the verified query/build contract, deterministic ordering and one evaluation time. Failed health/DB/binding checks produce unavailable/omitted dependent claims, not 404, zero counts, empty history or rankings over silently dropped dependencies. Counts/expected sets describe the governed projection, not an invented complete source universe. Delayed undetected storage corruption or malicious owner tampering is **outside application prevention**, including a physically missing row before detection; PostgreSQL checksums, backup/recovery verification and bounded integrity audits are operational prerequisites, not cryptographic per-query guarantees. Any reading of the specs requiring stronger immediate physical-corruption detection is an **implementation acceptance gate** requiring review before enablement, not a claim this design proves it.

Positive decisions are immutable, **process-local**, bound to I+exact adoption/generation receipt+policy/build+incarnation+g/lineage+health/integrity status and original deadline. Conservatively anchor lease to monotonic query start m0, using DB-clock expiry bounds: deadline ≤min(m0+30s, applicable E/other validity limits translated conservatively). A slow pre-revocation snapshot cannot install a fresh 30s lease at query completion. Track elapsed time/clock uncertainty, reject late results and fail closed on unbounded suspend/clock uncertainty; check deadline/E again before emitting protected bytes. Hits, retries, warm processes or failed DB revalidation cannot slide or restart the lease, including across processes.

Cache immutable raw projection inputs in protected process-local custody, with v2 key/envelope binding I, policy/build, incarnation, g/lineage, row/evidence references, normalized query/order/pagination, payload digest and evaluation semantics. Verify actual contents, not just matching metadata. Re-evaluate price eligibility, availability, promotion date windows, discounts, ranking/counts, history cutoff and degradation at one explicit evaluation time; raw input sets must include scheduled candidates needed for that evaluation. Rendered payload `validUntil` is the earliest relevant time transition, authority deadline or expiry. If input completeness beyond an evaluation boundary cannot be proved, expire/reload rather than reuse. Original historical times remain in DTOs.

Failed/unavailable DB revalidation **before the original deadline** may use only the existing positive decision and already-bound usable payload; a cache miss requiring DB fails unavailable. Confirmed ineligibility/revocation/corrupt required proof evicts immediately where observed. At/after deadline or expiry, failure is fail-closed. On payload miss with a cached decision, a fresh RR transaction must recheck exact authority/current g/health and load consistent projection inputs; cached authorization cannot label a separate current-table scan. On successful revalidation read current g/health: never stamp old payload with a new generation. A still-bound previous payload may survive its original short lease after a conforming update; it is bounded cached verified output, not retained historic serving. Legacy Redis envelope v1 is ignored/namespace-retired; Redis admission remains independent and unchanged. Shared payload storage is not enabled without equivalent trusted producer/custody/content binding.

External commercial responses must execute a deadline/authority gate at request time: remove long commercial ISR policies, use dynamic commercial output with internal bounded reuse and initially `private, no-cache, must-revalidate` HTTP semantics, including guarded validators/304/HEAD. No SWR/stale-if-error or extra CDN grace. Headers alone do not defeat a framework cache; built-server proof must show the handler/gate runs. A future external full-response cache is permitted only if its pre-response gate demonstrably preserves the same ≤30s/earlier-expiry bound. Keep static shell/taxonomy/assets cacheable; no blanket `no-store` or Cache Components migration.

Client/Router/PWA state consumes original remaining validity, conservatively subtracting transport/elapsed time, never starting a new lease on receipt. Revalidate/hide commercial state on navigation, prefetch reuse, deadline and resume/offline; no new calculation/current presentation from expired basket/suggestions. Commercial streaming/metadata must be gated before each protected emission or buffered as a bounded unit; reject late chunks. Already delivered content cannot be recalled or represented as freshly verified. Revocation proof records DB transition and observed readback as a bracket, not report time as exact commit; multiple-instance enforcement is measured conservatively from durable visibility, ≤30s and before earlier expiry. Notifications help but are not correctness.
