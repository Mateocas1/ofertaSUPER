## Objective and authority

Deliver an honest public search → exact GTIN comparison → freshness/availability → local five-product basket experience. This work unit is a child of `odd/tasks/consumer-mvp-reset.md`; preserve the completed CMVP-03 baseline and its frozen 500-target manifest. Existing public routes instead read guarded PostgreSQL serving projections; a snapshot gate does not publish or adopt those projections. Do not claim public readiness until the implemented public path matches the accepted architecture and is verified in its target deployment. Do not add a managed database, treat illustrative prices as live, relax exact-GTIN identity, or modify the frozen CMVP-03 evidence.

- [x] **CMVP04-B3 decision — bind the observation per offer (parent decision, with conviction).** Reasoning: a freshness PASS asserts that THIS offer reflects an observation of the source, and when. The current design cannot support that claim, and not merely weakly. Two defects compound: the freshness window is evaluated on `supermarket_products.last_checked_at`, which several writers still stamp with a processing clock, so the value deciding freshness does not mean observation time; and provenance is inferred by window corroboration, so any same-source durable capture of the same identity inside the window proves the offer with no binding to that offer. A fresh processing clock plus a roughly 23-hour-old same-identity capture therefore yields a fresh verdict, which is a false statement about the data rather than a conservative approximation. Window corroboration was accepted only because no foreign key exists from the product table and a migration was forbidden against the retained volume; a constraint justifies sequencing, never an unsound claim. Decision: add a nullable per-offer `observed_at` that only guarded source-observation paths write, and evaluate the freshness window on THAT value, keeping `last_checked_at` as the last write attempt. Durable-capture corroboration stays as an additional reported signal, never as a substitute for binding. Accepted consequence, deliberately: every pre-existing row has a null instant and is therefore unproven, so the retained volume can only ever report unproven or stale and can never produce a first-class PASS; any environment used to certify closure must have the migration applied. The migration is additive and nullable with no backfilling default, because a default would fabricate the very observation the column exists to prove. The retained volume is never migrated; a separate measurement environment is required, and the verified private backup makes restoring into a fresh volume the honest route. Implementation runs as CMVP04-B3 in its own worktree. Two provenance classes must never be indistinguishable in the artifact, which is why no freshness fallback is permitted.
